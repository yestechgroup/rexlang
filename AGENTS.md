# AGENTS.md

Rust cargo workspace. `.mox` modeling sources compile to a Core IR artifact; backends (Rust codegen, JSON Schema) consume only that IR. Language reference: `docs/LANGUAGE.md`; expression spec: `docs/EXPRESSIONS.md`.

## Pipeline (crate ownership)

Surfaces are parsed in `rex-syntax` (logos lexer + chumsky parser, one parse/fmt entry point per surface), resolved/validated/lowered in `rex-driver` (salsa-based: resolve, validate, lower, navigation index, diagnostics), and land as versioned `rex-ir` artifacts that `rex-backend-rust` / `rex-backend-jsonschema` / `rex-backend-cedar` and downstream consumers ingest. The **normative grammar (EBNF) per surface lives exactly once** in the parser module docs (`crates/rex-syntax/src/parser/mod.rs`); docs link to it instead of restating it (`.ifml`: the Pest grammar file; `.rosetta`: external toolchain). A new surface is a table row, not an appended sentence.

| `.ifml` interaction flow (views, navigation, and CLI `command` declarations) | **Pest** parser in `rex-ifml` (`parse_ifml`/`parse_ifml_file`) — not chumsky | `compile_ifml_str` (resolver + span index) → versioned `rex_ir::ifml::IfmlModel` (its `commands` vec is the CLI surface; typed args/options bind event expressions in `check_ifml`; no in-tree backend); `manifest_ifml` → versioned `rex_ir::ifml_manifest::IfmlManifest` (the declaration-backed control/route manifest, post-check, `rexlang manifest <file.ifml>`); `format_ifml` — no rex-driver stage | `docs/IFML.md` |
| `.rosetta` (Rune DSL) | **external, rev-pinned sigil toolchain — not ours to specify** | `import sigil` lowering: Rune namespaces → synthetic rexlang packages; normative contract in `crates/rex-driver/src/sigil.rs` | `docs/LANGUAGE.md` (Importing Rune models) |

- Backends must consume **only** `rex_ir::Model` (and, for Cedar, the `ActorModel` pair) — never the AST. Lowering happens in `rex-driver`.
- The serialized IR is a versioned wire format: camelCase, adjacent tagging, `formatVersion` gate. Contract and rules live in the `rex-ir` crate docs. New fields must be `#[serde(default)]` (+ `skip_serializing_if`) so body-less/vocabulary-less models stay **byte-identical** — golden tests enforce this.
- **Domain imports**: every compile entry point takes one `DomainImports` bundle (`SchemaImports`/`SigilImports` inside, keyed `(mox path, import path)`); `DomainImports::default()` provides nothing (→ `imported schema/sigil '<path>' was not provided`). The CLI resolves import content from disk (paths relative to the importing file — `.mox` sigil imports also walk the named file's directory for transitive rosetta imports; see Gotchas for the per-surface rules); the driver stays filesystem-free. For `.actor`/`.ddd` compiles the bundle carries each imported domain's import content keyed by the domain's path, so policies and designs target lowered rosetta/schema types.
- Plus `rex-expr` (expression parser/typechecker), `rex-vocab` (providers/lockfile), `rex-runtime` (generated code's support lib), `rex-backend-common` (backend-shared utilities: canonical JSON key order, the snake_case instance-id convention, the generated-file writer), `rex-lsp`, `rex-cli` (the `rexlang` binary), `rex-verify` (Creusot-specified semantic-graph kernel — contracts compile away on stable, proofs via `cargo creusot -p rex-verify` are run locally, not in CI; proof-obligation register in `docs/VERIFICATION.md`, and every `#[trusted]` there needs a register row).

## Commands

```sh
scripts/ci-local.sh              # THE gate: build, test, clippy, fmt, docs — every step must report *-OK before pushing
scripts/ci-local.sh audit        # the supply-chain gates (cargo deny check + cargo audit) — CI runs them as separate fast jobs
scripts/ci-local.sh build|test|clippy|fmt|docs    # one CI step at a time
cargo test -p rex-driver --test navigation      # one test suite
cargo run -p rex-cli -- check tests/conformance/                            # project mode + the union integrity pass: one snapshot of every supported surface under a dir; each file checks independently with its imports resolving map-first from the snapshot, then the standalone artifacts cluster into import-connected applications and the cross-layer wiring is diagnosed per application (formatter-golden `X.fmt.<ext>` artifacts are skipped — they are outputs whose imports/vocab resolve next to their sources, not standalone models)
cargo run -p rex-cli -- build tests/conformance/ -o target/rex               # project-mode artifact emission: one `<input path>.json` per file under the out dir (default `target/rex`), each the `rexlang ir` artifact for its surface
cargo run -p rex-cli -- explain E0104                                        # explain one diagnostic code from the rex-diagnostics registry (--list: the allocation ledger + every code)
REX_UPDATE_FIXTURES=1 cargo test --workspace    # regenerate golden files
```

CI (`.github/workflows/ci.yml`) **invokes `scripts/ci-local.sh` for every gate** (build, tests, clippy, fmt, docs) — the script is the single source of truth for the gate sequence and the `rexlang fmt --check` fixture-glob list (`FIXTURE_FORMAT_GLOBS`), so a new fixture directory is a one-file edit and local/remote can never drift (issue #121). CI also runs two fast supply-chain jobs: `cargo audit` (advisories — must stay at zero) and `cargo deny check` (advisories/licenses/bans/sources per `deny.toml`); the script's `audit` subcommand replicates both locally. A warning anywhere is a failure.

## Testing quirks

- **Golden fixtures** under `tests/conformance/` (IR artifacts, wire/api schemas, instances, fmt output) are byte-compared. Regenerate with `REX_UPDATE_FIXTURES=1`, then read the diff — goldens are the spec. Changing any emitter usually invalidates several goldens; body-less/vocabulary-less models must stay byte-identical.
- **Scratch-crate e2e** (`rex-backend-rust/tests/codegen_end_to_end.rs`): tests generate Rust code into a *separate cargo project* under `target/scratch/` and run `cargo test` in it (tries `--offline` first). Deleting `target/scratch/` is always safe; first run recompiles it (~10s). The scratch crate must keep `[workspace]` (empty) to stay out of ours.
- **Examples are CI-tested** (`examples/`): `examples_conformance` compiles each example, generates it into `target/scratch/rex-examples-test`, and runs behavioral assertions; `examples_schemas` validates `examples/instances/*.json` against generated wire schemas; `examples_cedar` (rex-backend-cedar) validates the `support` pair's Cedar output with the real `cedar-policy` crate under strict validation; `examples_artifacts` (rex-driver) compiles the artifact-surface examples (`.evt`/`.ddd`/`.uc`/`.deploy`/`.cmmn`) and byte-compares them against `examples/artifacts/` goldens; rex-backend-cmmn's examples test lowers `support.cmmn` to the cmmn-rs `CaseDefinition` JSON (`examples/artifacts/support.case.json`). Adding an example means adding its scratch assertions + instance (domain surfaces) or its artifact golden (artifact surfaces) — the harness fails otherwise. The domain-example list is hardcoded in three places: `examples_flow.rs`, `examples_schemas.rs`, and `rex-cli/tests/cli/`; the artifact-surface lists live in `crates/rex-driver/tests/examples_artifacts.rs` (with per-extension list↔disk sync tests); the `.ifml` examples (`examples/*.ifml`) have their own list in `crates/rex-ifml/tests/examples.rs` (compile + type-check + fmt-canonical + manifest byte-goldens under `examples/artifacts/<name>.manifest.json`); `rex-cli/tests/cli/` black-box `check`s the artifact examples too (`ARTIFACT_EXAMPLES`).
- **No network in tests**: `HttpProvider` is only URL-template unit-tested. `rexlang vocab fetch` is the only command that fetches.
- **LSP tests are in-process** via `LspService` + client socket (`tower-lsp` 0.20); the only subprocess test is the framed stdio handshake in `rex-cli`. The server dispatches by URI extension — `.mox` drives the salsa session, `.ifml` the rex-ifml one-shot compile (resolver + typed checker), `.ddd` the one-shot design compile (diagnostics only, no navigation; keyed by the disk path when the document has one, so imports resolve lexically), `.actor` the policy compile with grant coverage against the directory's `.ddd` artifacts (rexlang#128), `.dmn` the decision-model compile (diagnostics only — imports gather like `.ddd`, markdown tables read from disk next to the document, rexlang#151), everything else publishes no diagnostics. The `.ddd`/`.actor` capability joins resolve against the document's directory siblings (open documents win over disk; a non-compiling sibling contributes nothing). The tower-lsp client socket is a **capacity-1 channel**: tests must interleave reads (`next_publish`/`drain_socket`) with opens or the server's publish send deadlocks the handler.
- Wire-schema conformance validation uses the `jsonschema` crate against the committed golden schema; proptest suites (rex-backend-rust scratch, rex-backend-jsonschema) generate instances and validate round-trips — treat shrinking counterexamples as real bugs, not flaky tests.
- On this machine, `/tmp` is a small tmpfs and rustdoc doctest **linking SIGBUSes (or hangs) writing there**; run doctests (or full `cargo test`) with `TMPDIR` pointed at a disk-backed directory. Watch for orphaned `cargo`/`rustc`/`rust-lld` processes after killed builds — they stampede the load average and lock `target/`. **This hit CI too** (Oct 2026 incident: the runner's rex-driver doctests died with `ld terminated with signal 7 [Bus error]` and main stayed red for a day) — `.github/workflows/ci.yml` now frees runner disk, points `TMPDIR` at `target/tmp`, and caps the test step at `--jobs 2`; `scripts/ci-local.sh` replicates the five CI steps locally. A `signal 7` in CI's Doc-tests section is resource exhaustion — check `df -h` in the log, don't hunt a compiler bug. Before pushing: run `scripts/ci-local.sh` until every step reports `*-OK`. Before branching: check main's latest run is green.

## Gotchas

- `check_integrity` (rex-driver, issue #114, register row V12) is the union integrity pass: a pure function over path-tagged artifact buckets (`DddModel`/`ActorModel`/`EventModel`/`DeployModel`/`IfmlModel`). Diagnostics are span-less (artifacts are span-free by wire contract); the five non-capability checks are error severity, while the two capability checks (existence, coverage) are **warning severity since rexlang#128** — their joins resolve at compile time (rule 10 pooling a `&[ActorModel]` slice with the `unknownCapability` did-you-mean code; `compile_actors_str_with_designs` grant coverage with `grantedCapabilityUncarried`), and the pass is their lint channel. The compile-time joins run in the CLI project pipeline (`.ddd`/`.actor` arms gather sibling artifacts from the snapshot; an empty sibling set is exactly the plain behavior) and the LSP; the CLI's directory batch mode still hosts the pass ONLY in phase 2: `check_one` retains each successful file's artifact, contributions cluster into import-connected applications via union-find over canonicalized import paths (`.mox` files are bridge nodes; deploy/uc/cmmn contribute no bucket), unrelated applications in one checked tree never cross-check, and the pass's capability lint stays unprinted for files phase 1 already failed. `agent` is a keyword — never a bare `.ddd` param name; a standalone `cedar { ... }` grant entry serializes with an empty capability name (coverage skips it); action→op binding is ASCII-case-insensitive (`ApproveRefund` ↔ `approveRefund`).
- Capability nouns are classified against the aggregates (rexlang#144): with designs provided, `NounClassification` in `ddd/graph.rs` — pure over `(rex_ir::Model, &[rex_ir::ddd::DddModel])`, mirroring rule 6's predicate — warns when a capability is granted on a non-root (contained, repository-bearing) entity design (`a non-root aggregate member`, naming the aggregate root when derivable, help pointing at the root); value, root, and no-verdict (no design, dto, repository-less entity) stay silent. `compile_actor_file` builds the table only when designs are non-empty AND every domain lowered (`union_model`, the rule-6 discipline), `None` through `lower_actors` is byte-identical behavior, and the `.ddd` inline-actors path always passes `None` — actor lowering and the design registries never co-occur there (domains lower through the shared per-file union pipeline before designs exist; `compile_ddd_str_with_actors` receives pre-lowered `ActorModel`s).
- Machines are closed over their enum (V13): every machine state must be a literal of the machine's enum type, and `.ddd` `when` conditions (transition guards, service/repo op conditions) must type as boolean — the `.actor`/`.deploy`/`.cmmn` rule. Obligations are a declared vocabulary (V14): entries' `obligation` names resolve against the union of actors blocks' `obligation <name>;` declarations (purpose semantics), and action declarations' `target:` resolves to a domain class (E0109, skipped when the flow has no domains).
- `rex-syntax` permits `unsafe` (documented in its Cargo.toml): chumsky 0.10's `Input` trait requires `unsafe fn` implementations. Don't "fix" this; don't copy that custom `Input` impl elsewhere — `rex-expr` deliberately uses chumsky `Stream` + `.boxed()` levels instead (unboxed towers overflow the 2 MB test-thread stack).
- Comments: `lex()` drops comments for the parser; `lex_with_comments()` is what `fmt` uses. Parser spans are **byte offsets**; LSP maps them to UTF-16 (`rex-lsp/src/position.rs`).
- `id`/`readonly` are contextual identifiers, not keywords — they remain usable as feature names. Actor words (`actors actor agent capability grant permit forbid when obligation on never_both delegation purpose cedar import`) ARE real keywords, escapable with `^`. `schema`/`sigil` are contextual (only after `import`); `to` is contextual on delegation lines.
- `when` conditions are **fully type-checked** against the capability's class (single-file and `.actor` compiles) via rex-expr; the Cedar backend separately rejects constructs it cannot map at generate time (errors name the capability). Multiple obligations on one grant entry serialize as ONE Cedar annotation with comma-joined values (Cedar rejects duplicate annotation keys).
- `cedar-policy` is a **dev-dependency of rex-backend-cedar only** — the backend never links Cedar. It enables serde_json's `preserve_order`, which unifies workspace-wide and flips `serde_json::Map` to insertion order; emitters must canonicalize key order themselves (the shared `canonical_key_order` in `rex-backend-common`) or goldens drift.
- `rexlang fmt` dispatches by file extension (`.mox` vs `.actor` vs `.ddd` vs `.evt` vs `.deploy` vs `.uc` vs `.cmmn` vs `.ifml` formatters); stdin is treated as `.mox`.
- `.evt` conformance fixtures live in `tests/conformance/events/` (that's what the CI fmt gate covers); `tests/conformance/models/events.evt` is the deliberately **non-canonical** source that `tests/conformance/fmt/events.fmt.evt` golden-compares the formatter against — don't cite it as a canonical model or "fix" its spacing. Same relationship for `.deploy`: `tests/conformance/deploy/*.deploy` are canonical, `tests/conformance/models/deploy.deploy` is the formatter's golden source. Same for `.uc`: `tests/conformance/usecases/*.uc` are canonical (the CI gate covers them), `tests/conformance/models/usecases.uc` is the formatter's golden source. Same for `.cmmn`: `tests/conformance/cmmn/lending.cmmn` is canonical (the CI gate covers it), `tests/conformance/models/cmmn.cmmn` is the formatter's golden source. Same for `.dmn`: `tests/conformance/dmn/*.dmn` are canonical (the CI gate covers them), `tests/conformance/models/dmn.dmn` is the formatter's golden source.
- `.dmn` words are all contextual (`crates/rex-syntax/src/dmn.rs`); `version` is the one real lexer keyword (the `.mox` vocabulary precedent) and `import` is shared. Element names share ONE namespace per model. The `decision_model` grammar is the issue-rexlang#78 decision architecture: DRG first, logic attached — logic-less decisions are valid. Decision tables are **external markdown files** (dsntk shape, one table per file): the `.dmn` declares the input/output contract, the table implements it, and `compile_dmn_str`'s `tables` parameter carries contents keyed by the path **as written** (hosts resolve relative to the file; the driver stays filesystem-free). FEEL expression texts are syntax-checked via dsntk-feel-parser **except conditionals** — the rev-pinned parser mis-rejects `if <bare name> then`, composite `and`/`not` if-conditions, and nested ifs, so `contains_if_keyword` defers them (never false-positive on legitimate FEEL). dsntk crates are rev-pinned in `[workspace.dependencies]` (the sigil/restingstate discipline). `agent` is an `.actor` lexer keyword — never a `.dmn` input name unescaped (support.dmn uses `helper`).
- `.deploy` words are all contextual (tables in `crates/rex-syntax/src/deploy.rs`); `->` (`Token::Arrow`) is the one new lexer token, and setting *values* accept keyword tokens (`container` is a `.mox` keyword but an ordinary word in value position — the qname-segment rule). Policies are rex-expr conditions typed against a synthetic settings universe (`DomainTypes::insert_class`, never a fake `Model`) and evaluated by the driver's constant evaluator against effective settings (component baselines ⊕ profile defaults ⊕ overrides).
- `.actor` import resolution lives in the CLI (paths relative to the `.actor` file, read from disk); the driver receives texts only and stays filesystem-free (`compile_actors_str`). Import-path strings must match provided domain paths exactly.
- `.mox` `import schema "<path>" as <Alias>` registers a **nominal, feature-less class** (alias, else the file stem) in the package namespace — JSON content is validated but never lowered into features (v1 is opaque). `schema` is a contextual keyword (only after `import`); the driver stays filesystem-free via the `DomainImports` bundle every compile entry point takes (`SchemaImports`/`SigilImports` inside, keyed `(mox path, import path)`) — the CLI resolves paths relative to the `.mox` file, `DomainImports::default()` provides nothing (→ `imported schema '<path>' was not provided`). `rexlang fmt` hoists the declarations into a section directly after `package`.
- `.ifml` imports are keyed by the resolver as `(importing-file identity, import-as-written)`; hosts gather them through `rex_ifml::walk_ifml_imports` (shared traversal — the CLI collector and the examples harness are fetch closures over it) and must provide under the same identities or nested imports miss. The reference pattern library lives in `patterns/ifml/` — domain-agnostic modules composed via `use` inside module bodies; its wire shape is pinned by goldens under `tests/conformance/ifml/patterns/`.
- `rex_driver::workspace_imports` is the host-side bridge for `import schema`/`import sigil` disk resolution (the driver core stays filesystem-free): the CLI and the LSP both gather through it; `collect_for_source` re-keys under a driver key that differs from the disk path (the LSP keys documents by URI).
- `compile_ifml_lenient` is the LSP's entry: the strict `compile_ifml_str` Ok/Err contract stays, lenient always returns the (partial) compilation with its import index — completions/definitions work on broken code. `.ifml` references/rename match BY NAME across every open snapshot (a module's uses live in dependents the focused import closure never sees); rename validity is the string surface's (non-empty, no quotes/backslashes/newlines).
- `rexlang ir --expand <file.ifml>` inlines `use` sites into the resolved module contents (overrides applied, composition recursed) — the DEFAULT artifact keeps use references; expansion is opt-in and never serialized back into the strict artifact.
- The `.ifml` formatter is **token-based, not IR-based** (Pest drops comments) and is pinned to byte-identical round-trip of the canonical fixtures `tests/conformance/ifml/app.ifml` and `tests/conformance/ifml/cli.ifml` (commands) — those tests are the layout spec (80-column inline budget, call-argument binding blocks always expand, `column` runs align their `->`, declaration headers always expand (`view`/`command`/…), structural blank before `component`/`container`/`use`/`field`/`column`/`command`, interior source blanks preserved collapsed). Changing layout rules means re-formatting every `.ifml` fixture, example, and pattern file in the same commit.
- The `.ifml` checker (`check_ifml`) **silently defers** what the shared expression language cannot type: bare calls (`today()`, `score(...)`), `%`, the `~=`/`!~` regex ops, non-integral numbers, `Float`/`DateTime`-typed checks, generic (identifier) module-input types, expressions naming untyped event params, and everything when `domains: None`. Command expressions bind the command's typed arguments/options; **prompt names and generic command types are deferred** (prompt kinds are presentation semantics, not expression types), and option/prompt defaults get the structural literal rule only. That's the documented generation-time contract — don't "fix" the skips into errors. Literal-type checks on overrides are structural; deep navigation needs the folded `field_expr` grammar (one `.` segment chain).
- `.ifml` `.actor` imports are **load-bearing** (Phase A of #117): hosts compile them into `ActorModel`s for `check_ifml_with_actors` — an empty actors slice skips the authorization pass entirely (the `domains: None` contract). The CLI hard-errors on a missing or non-compiling policy; the LSP degrades to no authorization checking (open documents win over disk). `requires:`/`roles:` resolve bare-name union-wide against capability/actor tables; spans come from the index's `auth_sites` (never serialized — the IR is unchanged). E0107/E0108 live in rex-ifml's check/ directory; E0104–E0106 there are the interaction cross-reference — every diagnostic code is allocated in the central `rex-diagnostics` registry (`rexlang explain --list`); a new code is a table row there, never a local constant.
- The `.ifml` cross-reference pass (E0104–E0106) and the authorization pass (E0107/E0108) diagnose sites on the **entry file plus every module body it instantiates** (`instantiated_modules`: seeded by the entry file's `use` sites, closed over module composition via `resolved_module` + span containment). Sibling modules of the same imported file that the app never `use`s stay inert. `navigate` targets are views **or containers** (the index carries container sites; wizard steps). This is what makes pattern instantiation honest: the library's app-facing targets (`ItemDetail`, `Category`, `MarkRead`, …) stay undeclared in `patterns/ifml/` — `examples/support.ifml`/`ecommerce.ifml` carry the reference declaration blocks, and the library's internal wiring resolves itself (Wizard steps, SearchPanel's `results`; the `Pagination` pager deliberately carries no navigations).
- The control/route manifest (`rex_ir::ifml_manifest`, emitter `rex_ifml::manifest_ifml`, CLI `rexlang manifest <file.ifml>`; issue #118) is derived **post-check**: hosts gate emission on `check_ifml`, so every edge target is declaration-backed by construction (the #112 ingest-defect class is structurally impossible at this boundary — V11's enforcement names it). Controls/edges come from the **expanded** view tree (pattern splices indistinguishable from app-authored UI); routes/actions/commands are the entry file's declarations; `data:`/`target:` resolve to `(package, class)` only when the host provides the domain union and the name is unique (bare spelling always rides along). Goldens: `tests/conformance/ifml/{app,cli}.manifest.json` + `examples/artifacts/{cli,ecommerce,support}.manifest.json` (regenerate `REX_UPDATE_FIXTURES=1 cargo test -p rex-ifml`). It is a standalone versioned artifact (`IFML_MANIFEST_FORMAT_VERSION`) but deliberately NOT a classified kind in `artifact_check` (the IfmlModel precedent — root keys collide with it).
- `.cmmn` compiles against the four `.uc` buckets; plan items and case-file items share one namespace per case, and `when` conditions type-check against a synthetic case universe (the `.deploy` pattern: `case_file` + plan-item transition predicates + the case as root — `DomainTypes::insert_class`, never a fake `Model`). `rex-backend-cmmn` consumes `(CmmnModel, domain Model)` (the Cedar pair precedent) and lowers to the cmmn-rs `CaseDefinition` JSON — the FEEL-translatable rex-expr subset only, everything else a named generate-time error. Event on-parts and plan-item predicates in `when`s compile but are backend rejections (documented engine gaps, not authoring errors). Transition vocabularies live in the driver (the `.deploy` discipline): plan items `create/enable/start/complete/terminate/fail/occur`, case-file items `create/update/delete/addChild/removeChild`.
- Typed expression checking for ANY surface goes through `rex_expr::DomainTypes` (the public class/named-type index: `from_model`, `merge`, `insert_class`; `TypeContext` is a compatibility alias). Build/merge a `DomainTypes` rather than synthesizing a fake `rex_ir::Model` to call `TypeContext::from_model`.
- rex-expr resolves `EnumName.Member` through the `DomainTypes` enum-member registry (rule L3 of `docs/EXPRESSIONS.md`; fed by `from_model`/`insert_enum`), a non-member string literal compared against an enum-typed operand is a closed-set error, and the String-status guard lint warns use-based on `when`/filter guards but skips empty-string sentinels (rexlang#142).
- `rust` op bodies are emitted **verbatim** into the generated method; an `expr` body is parsed/typed/lowered at generate time (generate-time errors name the operation). No `rust` body ⇒ no generated method. Sigil functions are the function-side twin: the verbatim `"rosetta"` body target is carried, never emitted; a statement-bearing `func` also carries the driver-checked `"rune"` statement body (sigil mapping rule 8 — library functions never get one), which rex-backend-rust lowers to straight-line Rust (guards → `assert!` naming the guard, aliases → sequential `let`s, `set`/`add` → assignment/`push`, the output local at its declared default shape; an arena-reaching body takes `res: &Resource` as the first parameter). Stub contract: NO `"rune"` target ⇒ the `todo!()` stub (statement-less, or driver-deferred with one warning naming the function); a PRESENT target that fails decode/check/lower is a hard generate-time error naming the function + slot. Return multiplicity mirrors the parameter mapping on the wire (`returnMultiplicity`): `0..*` → `Vec<T>`, `0..1` → `Option<T>` — rex-expr types bare calls identically.
- Salsa session pattern (driver): `Database::new()` (Clone), `SourceFile::new(&db, path, text)`, `file.set_text(&mut db).to(...)`; tracked fns return rich `Clone + PartialEq` types (no Hash needed).
- `docs/EXPRESSIONS.md` rules R1–R4 are test-citable contracts (overflow, null-safe equality, Option propagation, division); lowering changes must keep them aligned.
